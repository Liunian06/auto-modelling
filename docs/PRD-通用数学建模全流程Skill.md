# PRD：通用数学建模竞赛 Skill

## 1. 产品目标

开发一个适用于不同 LLM 的数学建模竞赛 Skill，按照真人参赛过程完成赛前准备、赛中建模和赛后复盘。

Skill 的目标不是为不同能力的 LLM 设计不同流程，而是通过统一、清楚的 Workflow，引导执行模型充分探索问题、比较方案、完成实验并产出尽可能高质量的论文。

首期重点支持：

- 全国大学生数学建模竞赛（CUMCM，国赛）。
- 美国大学生数学建模竞赛（MCM/ICM，美赛）。
- 其他采用“赛题—建模—论文”形式的数学建模比赛。

## 2. 核心原则

- 所有比赛都使用统一的本地文件结构。
- Skill 中所有面向 LLM 的指令和说明文档必须使用中文编写，代码、命令、路径、文件名、API 名称及必须保留的专业术语除外。
- Skill 分为赛前、赛中、赛后三个阶段。
- 赛前积累的赛题、论文和分析应能在赛中直接使用。
- 赛中模仿真人参赛流程，逐步推进建模和论文工作。
- 不满足于第一个可行方案，应尽可能探索、比较和优化。
- 记录采用过、放弃过和验证失败的方案，避免重复试错。
- 赛中持续记录当前进度和交接信息，使不同 LLM 或 Agent 能接续工作。
- 赛题整理、分析、实验说明、审核记录、日志和复盘等过程性描述文件统一使用 Markdown。
- 正式论文统一使用 LaTeX 编写，源文件采用 UTF-8，并根据赛事要求选择合适的模板、文档类和编译引擎。
- 赛后复盘应沉淀为下一次比赛可复用的经验。
- 不虚构数据、实验结果、参考论文或引用。
- 国赛和美赛分别采用对应的论文语言、结构和表达重点。
- 当届格式、提交和 AI 使用规定以官方规则为准。

## 3. 三阶段 Workflow

### 3.1 赛前：资料整理与学习

赛前阶段用于整理历年比赛资料，分析优秀参考论文，为后续比赛建立可复用的知识积累。

#### 主要流程

1. 收集历年赛题和官方附件。
2. 按比赛、年份和题号建立统一目录。
3. 为每道赛题寻找多篇参考论文。
4. 阅读并分析参考论文。
5. 比较不同论文的建模路线和写作方式。
6. 提炼可以学习和复用的内容。
7. 将分析结果保存到对应赛题目录。

#### 参考论文分析内容

每篇参考论文至少分析：

- 如何理解和拆解题目。
- 使用了哪些数据和预处理方法。
- 为什么选择这些模型。
- 模型如何建立和求解。
- 如何进行参数调整、检验和误差分析。
- 图表如何服务于结论。
- 论文结构和表达有什么特点。
- 有哪些创新点。
- 有哪些不足或可以改进的地方。
- 哪些方法、代码思路或写作方式可以在其他比赛中复用。

#### 赛前产物

- 历年赛题和附件。
- 多篇参考论文。
- 单篇参考论文分析。
- 多篇论文横向比较。
- 可复用方法与写作经验总结。

### 3.2 赛中：完整建模与论文产出

赛中阶段模仿真人参赛流程，从拿到赛题开始，逐步完成建模、实验和论文。

#### 赛中流程

1. **问题整理**
   - 整理赛题、附件、提交要求和比赛限制。
   - 明确题目包含哪些子问题以及最终需要交付什么。

2. **问题分析**
   - 分析问题背景、目标、变量、约束和子问题关系。
   - 形成对题目的清晰理解和建模任务清单。

3. **数据预处理**
   - 检查数据字段、单位、缺失值、异常值和重复值。
   - 完成清洗、转换、特征构造和必要的探索性分析。
   - 记录每项处理的原因。

4. **模型选择**
   - 根据题目和数据提出多个候选模型。
   - 比较模型的适用性、假设、实现成本、可解释性和验证方式。
   - 选择当前主模型，同时保留备选方案和放弃理由。

5. **模型构建**
   - 写出数学表达、算法流程和代码实现。
   - 运行模型，并将模型结果、预测数据、评估指标、求解结果等实际输出保存到 `工作区\结果\`。
   - 确保论文中的结果能够追溯到真实计算。

6. **模型调优**
   - 调整参数、特征、模型结构或求解方法。
   - 与基线和其他候选方案进行比较。
   - 进行灵敏度、稳健性、误差或其他必要检验。
   - 记录每轮尝试、结果和选择理由。

7. **论文编写**
   - 在写作前确定赛事模板、LaTeX 文档类和编译引擎，并在日志中记录选择理由。
   - 使用 UTF-8 编码的 LaTeX 源文件作为正式论文主稿。
   - 根据真实建模过程编写摘要、问题重述、假设、符号、模型、求解、检验、评价和结论。
   - 插入真实图表和结果。
   - 使用经过核实的引用。

8. **论文优化**
   - 在 LaTeX 主稿中优化摘要、结构、逻辑、语言、公式、图表和结果解释。
   - 检查每个子问题是否得到明确回答。
   - 按目标赛事调整论文风格。

9. **论文审核**
   - 检查题目覆盖、数学正确性、数据来源、实验真实性和结果一致性。
   - 检查符号、公式、代码、图表和正文是否对应。
   - 编译 LaTeX，检查致命错误、缺失引用、未定义交叉引用、图片路径和字体。
   - 检查引用、匿名、文件格式、页数和当届提交要求。
   - 修复阻塞问题后，保留可编译的 `.tex` 源文件和成功编译的最终 PDF。

#### 过程文件与最终论文格式

过程性描述文件统一使用 Markdown，包括但不限于：

- 赛题整理和要求清单。
- 问题分析和子问题拆解。
- 数据预处理说明。
- 模型候选、选择依据和放弃理由。
- 模型构建与调优记录。
- 实验说明和结果解释。
- 论文审核与修复记录。
- 赛中进度与交接日志。
- 赛后复盘和经验总结。

过程性 Markdown 文件保存到内容对应的目录。例如：

- `赛题\赛题整理.md` 保存赛题整理。
- `参考论文\` 保存参考论文分析 Markdown。
- `工作区\数据\` 保存数据预处理说明 Markdown。
- `工作区\日志\` 保存模型决策、进度、审核和交接 Markdown。
- `复盘\` 保存复盘 Markdown。

正式论文使用 LaTeX：

- LaTeX 源文件统一使用 UTF-8。
- 正式论文主文件使用 `.tex`。
- 参考文献优先使用 `.bib` 管理；赛事模板另有要求时遵循模板。
- 官方提供的 `.cls`、`.sty`、封面或其他模板依赖与论文源文件一起保存在 `工作区\论文\`。
- 编译得到的最终 PDF 保存在 `工作区\论文\`。
- 正式论文从论文编写阶段开始以 LaTeX 为主源，不以 Markdown、Word 或其他格式作为最终论文源文件。

LaTeX 选择顺序：

1. 优先使用当届赛事官方模板、文档类和官方指定的编译引擎。
2. 官方没有明确要求时，遵循用户指定的可用模板。
3. 中文或中英混排论文默认选择 UTF-8、XeLaTeX 和 `ctexart`。
4. 纯英文论文在没有特殊字体或 Unicode 要求时，默认选择 UTF-8、pdfLaTeX 和 `article`。
5. 仅在官方模板、字体或宏包明确需要时选择 LuaLaTeX。

确定模板、文档类和编译引擎后，在 `工作区\日志\` 记录选择、版本和理由。不得在没有说明的情况下随意切换编译引擎。

#### 赛中日志与交接

赛中在 `工作区\日志\` 持续记录进度。每次完成一个主要步骤、作出重要决策、遇到阻塞或准备更换 LLM/Agent 时更新日志。

日志至少记录：

- 更新时间和当前负责人。
- 当前处于赛中九步流程的哪一步。
- 已完成事项及其结果。
- 关键决定、采用或放弃理由。
- 相关数据、代码、结果、图表和论文文件路径。
- 未完成事项和已知问题。
- 阻塞、风险与需要确认的内容。
- 下一步可以直接执行的操作。

新的 LLM 或 Agent 接手时，先读取日志及其中引用的文件，再继续执行。接手者不得仅凭对话上下文猜测当前进度；完成工作或再次交接前，应更新日志。

#### 探索要求

赛中不应只保存最终采用的模型，还应记录：

- 尝试过的候选方案。
- 每个方案的核心思路。
- 对应的代码和实验。
- 方案之间的比较结果。
- 被采用、放弃或暂停的原因。
- 模型调优过程和结果变化。
- 论文各版本的主要修改。

这些记录用于比赛中继续探索、切换方案、让其他 LLM 接手，以及赛后复盘。

#### 赛中产物

- 问题分析文档。
- 数据和预处理结果。
- 候选模型与比较记录。
- 模型代码、配置和运行结果。
- 图表和表格。
- 赛中进度和交接日志。
- LaTeX 论文草稿、优化稿、最终源文件和编译后的 PDF。
- 审核清单与问题修复记录。

### 3.3 赛后：复盘与沉淀

赛后阶段用于复盘整个参赛过程，将本次经验转化为下一次比赛可以使用的资料。

#### 主要流程

1. 整理最终赛题、数据、代码、论文和提交版本。
2. 回顾问题理解是否准确。
3. 回顾候选模型是否充分，模型选择是否合理。
4. 分析数据处理、代码实现、模型调优和验证中的问题。
5. 分析论文结构、表达、图表和审核中的问题。
6. 复盘时间分配和团队协作。
7. 结合比赛成绩、评语或外部反馈分析差距。
8. 总结做得好的地方、失败的地方和下一次改进项。
9. 提炼可复用的方法、代码思路、论文表达和检查清单。
10. 将复盘结果保存在对应赛题目录，供以后检索。

#### 赛后产物

- 完整比赛归档。
- 参赛过程复盘。
- 模型与实验复盘。
- 论文复盘。
- 时间与协作复盘。
- 可复用经验总结。
- 下一次比赛的改进清单。

## 4. Skill 开发、安装与用户数据分离

### 4.1 Skill 开发目录

开发和用户审核期间，Skill 保存在当前项目文件夹的 `.codex\skills\` 下：

```text
<当前项目文件夹>\
└── .codex\
    └── skills\
        └── <skill-name>\
            ├── SKILL.md
            ├── references\
            └── scripts\
```

本项目的实际开发位置为：

```text
E:\NewAI\auto-modelling\.codex\skills\<skill-name>\
```

Skill 不需要 `agents\` 和 `assets\` 文件夹，开发时不得创建这两个文件夹。

### 4.2 用户审核与安装

Skill 开发和测试完成后，先保留在项目开发目录中交给用户审核。只有用户明确审核通过并同意安装后，才能安装到用户 Skill 目录：

```text
%USERPROFILE%\.codex\skills\<skill-name>\
├── SKILL.md
├── references\
└── scripts\
```

规则：

- 用户审核通过前，不得将 Skill 提前安装到用户目录。
- 用户审核通过前，不得覆盖用户目录中已有的同名 Skill。
- 安装内容必须与用户审核通过的版本一致。
- 开发目录和安装目录只保存 Skill 自身的指令、参考资料和脚本。
- 开发目录和安装目录都不保存用户的赛题、参考论文、代码、结果、论文或复盘。

### 4.3 用户数据目录

用户在使用 Skill 时需要指定一个工作目录。所有比赛资料统一放在该工作目录下的 `data\` 中：

```text
<用户指定的工作目录>\
└── data\
```

例如用户指定 `E:\数学建模`，则数据根目录为：

```text
E:\数学建模\data\
```

规则：

- 用户已经指定工作目录时，使用该目录。
- 用户没有指定工作目录时，Skill 必须先询问。
- 不得把 Skill 开发目录作为用户工作目录。
- 不得把 Skill 安装目录作为用户工作目录。
- 不得在项目或用户目录的 `.codex\skills\<skill-name>\` 下创建 `data\`。
- 不得擅自把当前目录或 Skill 开发仓库当作用户工作目录。

### 4.4 比赛目录

每场比赛建立一个目录，命名格式为：

```text
{年份}{月份}-{中文简称}{英文标识}{届次年份}
```

示例：

```text
202509-国赛CUMCM2025
202502-美赛MCM2025
```

其中：

- `{年份}` 使用四位数字。
- `{月份}` 使用两位数字。
- `{中文简称}` 使用稳定、常用的中文比赛简称，例如“国赛”“美赛”。
- `{英文标识}` 使用稳定的官方或通用英文缩写，例如 `CUMCM`、`MCM`。
- `{届次年份}` 使用四位数字，表示该届比赛年份。
- 中文简称、英文标识和届次年份连续书写，中间不添加空格或连接符。

其他比赛也使用同一规则。例如某比赛的中文简称为“某某杯”、英文标识为 `ABC`、届次年份为 `2026`，则比赛标识部分写成 `某某杯ABC2026`。

### 4.5 赛题目录

每道赛题在比赛目录下建立独立文件夹，命名格式为：

```text
{比赛目录名}-{题号}
```

示例：

```text
202509-国赛CUMCM2025-A题
202509-国赛CUMCM2025-B题
202502-美赛MCM2025-A题
```

### 4.6 赛题内部结构

每道赛题统一使用以下结构：

```text
<用户指定的工作目录>\
└── data\
    └── 202509-国赛CUMCM2025\
        ├── 202509-国赛CUMCM2025-A题\
        │   ├── 赛题\
        │   ├── 参考论文\
        │   ├── 工作区\
        │   │   ├── 数据\
        │   │   ├── 代码\
        │   │   ├── 结果\
        │   │   ├── 图表\
        │   │   ├── 日志\
        │   │   └── 论文\
        │   └── 复盘\
        ├── 202509-国赛CUMCM2025-B题\
        └── 202509-国赛CUMCM2025-C题\
```

各目录用途：

| 目录 | 用途 |
|---|---|
| `赛题/` | 保存官方赛题、附件和官方说明 |
| `参考论文/` | 保存找到的参考论文及其分析 |
| `工作区/数据/` | 保存原始数据副本、清洗数据和中间数据 |
| `工作区/代码/` | 保存建模、实验、验证和出图代码 |
| `工作区/结果/` | 保存代码实际运行产生的模型结果、预测数据、评估指标、求解结果等输出文件 |
| `工作区/图表/` | 保存论文使用或候选使用的图表 |
| `工作区/日志/` | 保存赛中进度、关键决定、阻塞、下一步和 LLM/Agent 交接信息 |
| `工作区/论文/` | 保存 UTF-8 LaTeX 论文源文件、`.bib`、官方模板依赖、论文版本和编译后的 PDF |
| `复盘/` | 保存赛后复盘和可复用经验 |

不需要使用的空子目录可以暂不创建，但比赛目录和赛题目录的命名必须保持统一。

## 5. 主 `SKILL.md` 必须包含的内容

统一文件结构是 Skill 正常工作的基础，因此不能只写在 PRD 或其他参考文档中。

未来创建主 `SKILL.md` 时，必须在正文中直接写明：

1. Skill 开发目录、安装目录和用户数据目录互相分离，用户数据不得保存在 Skill 开发目录或安装目录中。
2. 用户必须指定工作目录；数据根目录是 `<用户指定的工作目录>\data\`。
3. 用户未指定工作目录时，Skill 必须先询问，不能自行选择。
4. 比赛目录命名规则：`{年份}{月份}-{中文简称}{英文标识}{届次年份}`。
5. 赛题目录命名规则：`{比赛目录名}-{题号}`。
6. 赛题内部的 `赛题\`、`参考论文\`、`工作区\`、`复盘\` 结构，以及 `工作区\` 内的 `数据\`、`代码\`、`结果\`、`图表\`、`日志\`、`论文\` 结构。
7. Skill 开始任务时要先判断属于赛前、赛中还是赛后。
8. Skill 开始处理比赛或赛题时，要先确认用户工作目录并检查对应目录是否存在。
9. 目录不存在时，按统一规则创建；目录已经存在时，在原目录中继续，不重复建立另一套结构。
10. 所有新产生的资料应保存到用户工作目录中的当前比赛和赛题目录。
11. 赛前资料、赛中成果和赛后复盘使用同一赛题目录连续积累。
12. 读取历史资料时优先从用户指定的 `data\` 中检索相同比赛、相似题目和参考论文分析。
13. 赛中在 `工作区\日志\` 持续记录进度；接手任务前先读取日志，完成阶段或准备交接前更新日志。
14. 代码实际运行产生的模型结果、预测数据、评估指标和求解结果等输出文件统一保存到 `工作区\结果\`。
15. 赛题整理和过程性描述文件统一使用 Markdown；正式论文统一使用 UTF-8 LaTeX。
16. 正式论文先按当届官方要求选择模板和编译引擎；无官方要求时根据论文语言和字体需求选择 XeLaTeX、pdfLaTeX 或 LuaLaTeX，并在日志中记录理由。
17. 最终论文必须保留可编译的 `.tex` 源文件和成功编译的 PDF。

主 `SKILL.md` 可以链接更详细的文件管理说明，但上述命名规则和目录示例必须直接保留在主文件中，不能只写一句“参见参考文档”。

## 6. 赛事适配

### 6.1 国赛

- 默认使用中文论文表达。
- 当届官方提供 LaTeX 模板或指定格式时优先使用。
- 无官方 LaTeX 模板或编译引擎要求时，默认使用 UTF-8、XeLaTeX 和 `ctexart`。
- 逐项回应题目问题。
- 重视模型假设、建立、求解、检验和结果对应关系。
- 摘要需要覆盖主要方法、关键结果和结论。
- 具体格式以当届官方要求为准。

### 6.2 美赛

- 默认使用英文论文表达。
- 当届官方提供 LaTeX 模板或指定编译方式时优先使用。
- 无官方要求且论文为纯英文时，默认使用 UTF-8、pdfLaTeX 和 `article`。
- 重视清晰叙事、模型选择理由、结果意义和现实建议。
- Summary 应能够独立说明问题、方法、结果和主要结论。
- 题目要求 memo、letter 等体裁时按要求编写。
- 具体格式以当届官方要求为准。

## 7. MVP 范围

首个可用版本需要实现：

- 在当前项目的 `.codex\skills\<skill-name>\` 中开发 Skill，且不创建 `agents\` 和 `assets\`。
- 判断用户处于赛前、赛中还是赛后。
- 获取或确认用户指定的工作目录。
- 按统一规则创建和读取 `<用户指定的工作目录>\data\` 下的比赛与赛题目录。
- 赛前整理赛题、参考论文并生成论文分析。
- 赛中执行九个建模与论文步骤。
- 将代码实际运行产生的模型结果、预测数据、评估指标和求解结果保存到 `工作区\结果\`。
- 保存候选方案、实验、论文版本和审核记录。
- 在 `工作区\日志\` 保存赛中进度和交接信息，支持不同 LLM 或 Agent 接续工作。
- 使用 Markdown 生成赛题整理和过程性描述文件。
- 根据赛事要求选择 LaTeX 模板和编译引擎，使用 UTF-8 LaTeX 编写正式论文并成功编译 PDF。
- 赛后生成复盘与可复用经验总结。
- 支持国赛和美赛基本论文风格适配。
- 防止虚构数据、实验和引用。

首期不要求：

- 建立独立 Web 平台。
- 自动提交比赛论文。
- 内置所有数学模型和算法代码。
- 保证获奖或保证不同 LLM 得到相同结果。
- 一次性整理全部历史比赛资料。

## 8. 验收标准

MVP 完成时应满足：

1. Skill 在当前项目的 `.codex\skills\<skill-name>\` 中开发，只包含 `SKILL.md`、`references\` 和 `scripts\`，不包含 `agents\` 或 `assets\`。
2. 用户审核通过前不会安装或覆盖用户目录中的 Skill；审核通过并得到安装许可后，安装版本与审核版本一致。
3. 主 `SKILL.md` 中直接包含 Skill 与用户数据分离规则、文件结构和命名规则。
4. 未指定工作目录时会先询问，不在 Skill 开发目录、安装目录或开发仓库中创建用户数据。
5. 能在用户指定工作目录的 `data\` 下，为一场比赛建立正确的比赛目录和多个赛题目录。
6. 赛前能为一道历史赛题整理多篇参考论文并形成分析。
7. 赛中能按九个步骤从赛题推进到最终论文审核。
8. 赛中产生的文件能保存到正确目录。
9. 代码实际运行产生的模型结果、预测数据、评估指标和求解结果能保存到 `工作区\结果\`。
10. 能记录候选模型、方案比较、放弃理由和论文版本。
11. 能在 `工作区\日志\` 记录当前步骤、已完成事项、关键决定、相关文件、未完成事项、阻塞和下一步。
12. 新的 LLM 或 Agent 能先读取日志和相关文件，在不依赖上一段对话上下文的情况下接续工作。
13. 赛后能生成结构化复盘和下一次改进项。
14. 能从历史赛题目录中找到并复用适用的经验。
15. 国赛和美赛论文在语言和表达重点上有明确差异。
16. 赛题整理、问题分析、模型记录、审核、日志和复盘等过程性描述文件使用 Markdown。
17. 正式论文使用 UTF-8 LaTeX，并根据当届官方模板、论文语言和字体需求选择合适的文档类与编译引擎。
18. 最终论文包含可编译的 `.tex` 源文件和成功编译的 PDF，不存在致命编译错误、缺失引用或未定义交叉引用。
19. 不把未运行的实验、未核实的引用或往届规则写成当前事实。

## 9. 后续开发顺序

1. 在当前项目的 `.codex\skills\<skill-name>\` 中创建主 `SKILL.md`、`references\` 和 `scripts\`，不创建 `agents\` 或 `assets\`。
2. 实现用户工作目录的询问与确认逻辑。
3. 实现在用户指定工作目录下创建 `data\`、比赛目录和赛题目录的逻辑。
4. 实现赛前参考论文整理与分析流程。
5. 实现赛中九步流程。
6. 实现赛后复盘流程。
7. 增加国赛和美赛写作参考。
8. 实现 Markdown 过程文件规范、LaTeX 模板选择和论文编译审核流程。
9. 使用历史赛题测试完整流程并迭代。
10. 将完成开发和测试的版本交给用户审核；用户明确审核通过并同意安装后，再安装到用户 Skill 目录。
