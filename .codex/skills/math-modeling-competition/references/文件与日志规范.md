# 文件与日志规范

## 目录

- 基本原则。
- 推荐命名。
- 日志文件。
- 日志模板。
- 更新时机。
- 接手流程。

## 1. 基本原则

- 文件放到内容对应的目录。
- 过程性描述使用 Markdown。
- 运行输出只放到 `工作区\结果\`。
- 图表只放到 `工作区\图表\`。
- 正式论文只以 LaTeX 为主源并放到 `工作区\论文\`。
- 进度、决策和交接放到 `工作区\日志\`。
- 不覆盖原始赛题、原始数据和参考论文。

## 2. 推荐命名

名称应能表达内容和阶段。

示例：

```text
赛题整理.md
参考论文-作者-简短标题.pdf
参考论文-作者-简短标题-分析.md
数据预处理说明.md
模型选择记录.md
模型调优记录.md
预测结果.csv
模型评估指标.json
灵敏度分析.png
论文审核记录.md
赛中进度与交接日志.md
main-draft.tex
main-final.tex
final-paper.pdf
比赛复盘.md
```

避免：

```text
新建文档.md
结果2.csv
最终版.tex
最终版2.tex
真的最终版.pdf
```

## 3. 日志文件

每道题维护一个主要日志：

```text
工作区\日志\赛中进度与交接日志.md
```

如果日志过长，可以按日期拆分，但必须保留一个当前入口文件，指向最新记录。

## 5. 更新时机

在以下时机更新日志：

- 完成一个主要步骤后。
- 作出重要模型或论文决策后。
- 运行关键实验后。
- 发现结果不可信或需要回退后。
- 遇到阻塞时。
- 更换 LLM、Agent 或人员前。
- 本轮工作结束前。

## 6. 接手流程

接手者依次执行：

1. 读取主要日志。
2. 检查当前阶段和下一步。
3. 打开关键文件。
4. 验证文件是否存在、结果是否真实。
5. 检查代码是否可运行。
6. 用简短 Markdown 补充接手确认。
7. 继续执行，不重复已完成工作。

日志不是结果文件。不要把大量运行输出粘贴进日志，改为引用 `工作区\结果\` 中的文件。
