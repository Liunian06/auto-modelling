# 通用数学建模竞赛全流程

## 版本信息

- 技能版本：`0.1.0`
- 版本格式：`MAJOR.MINOR.PATCH`，遵循语义化版本规则。
- `MAJOR`：Workflow、目录契约或产物格式发生不兼容变更，需要重新审核和安装。
- `MINOR`：向后兼容地增加阶段能力、参考规范或脚本功能。
- `PATCH`：向后兼容地修复说明、脚本缺陷或校验问题。
- 每次发布或交付 Skill 前，必须更新本节版本号，并在交接或发布说明中记录变更内容。
- 用户审核和安装时，以 `SKILL.md` 中的版本号作为实际安装版本；不得只根据 Git 提交号或文件修改时间判断版本。

## 核心目标

按照真人参加数学建模竞赛的过程推进任务，充分探索和比较候选方案，保存真实实验与选择依据，最终形成可复核的结果和高质量论文。

对不同能力的 LLM 使用同一套流程。不要设计“保底流程”和“上探流程”，也不要满足于第一个可行方案。在时间与算力允许的范围内持续比较、验证和优化，并记录探索过程，供赛中接力和跨比赛复用。

## 强制规则

1. 全部面向 LLM 的指令和说明文档使用中文。代码、命令、路径、文件名、API 名称及必须保留的专业术语可以使用英文。
2. 不虚构赛题、规则、数据、参考论文、引用、代码运行结果、模型指标或结论。
3. 论文中的数字、表格、图表和结论必须能追溯到真实数据、代码或可复核计算。
4. 当届官方模板、提交规范、页数限制、匿名要求和 AI 使用规则优先于本 Skill 的默认规则。需要当前规则时先查证官方来源。
5. Skill 文件与用户比赛数据分离。不得在 Skill 开发目录或安装目录中保存赛题、数据、代码、结果、论文或复盘。
6. 用户未明确指定工作目录时，先询问工作目录；不得把当前目录、Skill 目录或开发仓库自动当作用户数据目录。
7. 接续已有任务时，先读取 `工作区\日志\` 和日志引用的文件，不得只凭对话上下文猜测进度。
8. 未经用户明确许可，不覆盖已有文件；需要生成新版本时使用清晰的版本名。

## 开始任务

按以下顺序开始：

1. 确认用户指定的工作目录。
2. 判断任务属于赛前、赛中还是赛后。
3. 确认比赛年月、中文简称、英文标识、届次年份和题号。
4. 检查对应比赛与赛题目录是否存在。
5. 如果目录已存在，先检查文件和日志后继续；不要建立第二套目录。
6. 如果目录不存在，使用统一命名创建。
7. 明确本轮目标、可用时间、已有材料、交付物和验证方式。

可使用 `scripts/workspace_manager.py` 创建或检查目录。运行前先确认目标路径是用户指定的工作目录。

初始化示例：

```powershell
python "<Skill目录>\scripts\workspace_manager.py" init `
  --workdir "E:\数学建模" `
  --year-month 202509 `
  --chinese-name "国赛" `
  --identifier CUMCM `
  --edition 2025 `
  --problems A B C
```

检查示例：

```powershell
python "<Skill目录>\scripts\workspace_manager.py" inspect `
  --workdir "E:\数学建模" `
  --competition "202509-国赛CUMCM2025" `
  --problem A
```

脚本输出中文 JSON。根据 `成功`、`缺失目录`、`新建文件` 和 `保留文件` 判断状态，不要只依据退出码猜测。

## 统一目录

比赛目录命名：

```text
{年份}{月份}-{中文简称}{英文标识}{届次年份}
```

示例：

```text
202509-国赛CUMCM2025
202502-美赛MCM2025
```

中文简称、英文标识和届次年份连续书写，不添加空格或额外连接符。

赛题目录命名：

```text
{比赛目录名}-{题号}
```

示例：

```text
202509-国赛CUMCM2025-A题
202502-美赛MCM2025-A题
```

完整结构：

```text
<用户指定的工作目录>\
└── data\
    └── 202509-国赛CUMCM2025\
        ├── 202509-国赛CUMCM2025-A题\
        │   ├── 赛题\
        │   ├── 参考论文\
        │   ├── 工作区\
        │   │   ├── 数据\
        │   │   ├── 代码\
        │   │   ├── 结果\
        │   │   ├── 图表\
        │   │   ├── 日志\
        │   │   └── 论文\
        │   └── 复盘\
        ├── 202509-国赛CUMCM2025-B题\
        └── 202509-国赛CUMCM2025-C题\
```

目录职责：

- `赛题\`：保存官方赛题、附件、官方说明和 Markdown 赛题整理。
- `参考论文\`：保存参考论文原文、单篇分析和横向比较。
- `工作区\数据\`：保存原始数据副本、清洗数据、中间数据和数据处理说明。
- `工作区\代码\`：保存预处理、建模、实验、验证和出图代码。
- `工作区\结果\`：只保存代码实际运行产生的模型结果、预测数据、评估指标、求解结果等输出文件。
- `工作区\图表\`：保存分析和论文使用的图表。
- `工作区\日志\`：保存赛程进度、关键决定、阻塞、审核记录、下一步和 LLM/Agent 交接信息。
- `工作区\论文\`：保存 UTF-8 LaTeX 源文件、`.bib`、赛事模板依赖、论文版本和编译后的 PDF。
- `复盘\`：保存赛后复盘和可复用经验。

目录不存在时按需创建；目录已经存在时继续使用。不要创建空的重复结构。

## 三阶段 Workflow

### 赛前

1. 收集历年赛题、附件和官方说明。
2. 按比赛、年份和题号整理目录。
3. 为每道题寻找多篇真实参考论文。
4. 分析每篇论文的问题拆解、数据处理、模型选择、模型构建、验证、图表、写作、创新和不足。
5. 横向比较不同论文的路线和质量。
6. 提炼可复用的方法、代码思路、论文表达和检查清单。
7. 将整理与分析保存为 Markdown。

执行赛前任务时读取 [references/赛前流程.md](references/赛前流程.md)。

### 赛中

严格按九步推进：

1. 问题整理。
2. 问题分析。
3. 数据预处理。
4. 模型选择。
5. 模型构建。
6. 模型调优。
7. 论文编写。
8. 论文优化。
9. 论文审核。

每一步都要：

- 明确输入、输出和完成标准。
- 保存过程性 Markdown。
- 保存真实代码、运行结果和图表。
- 比较合理的候选方案，不只保留最终方案。
- 记录采用、放弃或暂停的理由。
- 在阶段完成、重要决策、阻塞或交接前更新日志。

执行赛中任务时读取 [references/赛中九步流程.md](references/赛中九步流程.md)。开始论文编写前再读取 [references/论文与LaTeX规范.md](references/论文与LaTeX规范.md)。

### 赛后

1. 归档赛题、数据、代码、结果、图表、日志和最终论文。
2. 复盘问题理解、模型选择、实现、调优、验证和论文表达。
3. 复盘时间分配、团队协作和 LLM/Agent 交接。
4. 结合成绩、评语或外部反馈分析差距。
5. 总结成功经验、失败原因和下一次改进项。
6. 提炼可跨比赛复用的方法、代码思路、写作表达和检查清单。

执行赛后任务时读取 [references/赛后复盘.md](references/赛后复盘.md)。

## 过程文件与正式论文

赛题整理、问题分析、数据处理说明、模型记录、实验说明、审核记录、日志和复盘统一使用 Markdown。

进入论文编写阶段后，正式论文以 LaTeX 为主源：

1. `.tex` 和 `.bib` 统一使用 UTF-8。
2. 优先使用当届官方模板、文档类和指定编译引擎。
3. 官方无要求时，遵循用户指定的可用模板。
4. 中文或中英混排默认使用 XeLaTeX 和 `ctexart`。
5. 纯英文且无特殊字体或 Unicode 要求时默认使用 pdfLaTeX 和 `article`。
6. 仅在官方模板、字体或宏包明确需要时使用 LuaLaTeX。
7. 在日志中记录模板来源、版本、文档类、编译引擎和选择理由。
8. 最终同时保留可编译的 `.tex` 源文件和成功编译的 PDF。
9. 检查致命错误、缺失引用、未定义交叉引用、图片路径、字体、匿名、页数和提交格式。

最终论文不能只有 Markdown、Word、PDF 或未经编译验证的 `.tex`。

## 日志与无缝交接

每道题在 `工作区\日志\` 中维护当前进度和交接记录。日志至少包含：

- 更新时间和当前负责人。
- 当前阶段及九步流程位置。
- 本轮目标。
- 已完成事项与结果。
- 关键决定及依据。
- 采用、放弃和暂停的方案。
- 相关数据、代码、结果、图表和论文路径。
- 未完成事项。
- 已知问题、风险和阻塞。
- 下一步可直接执行的操作。

新 LLM 或 Agent 接手时：

1. 先读取最新日志。
2. 打开日志引用的关键文件。
3. 核对实际文件和运行状态。
4. 用自己的语言总结当前状态。
5. 从日志中的下一步继续，不重复已经完成的工作。
6. 完成工作或再次交接前更新日志。

文件命名和日志模板详见 [references/文件与日志规范.md](references/文件与日志规范.md)。

## 赛事适配

- 国赛默认使用中文论文表达，强调逐项回应、模型假设、建立、求解、检验和结果对应关系。
- 美赛默认使用英文论文表达，强调清晰叙事、模型选择理由、结果意义、现实建议和独立完整的 Summary。
- 其他比赛先读取当届官方规则，再在通用九步流程上调整论文语言、模板、体裁和侧重点。

具体规则详见 [references/赛事与论文适配.md](references/赛事与论文适配.md)。

## 完成标准

只有同时满足以下条件，才能声明本轮任务完成：

1. 请求范围内的产物已经实际写入正确目录。
2. 代码已真实运行，结果文件存在并可复核。
3. 过程性说明使用 Markdown。
4. 正式论文使用 UTF-8 LaTeX，最终 `.tex` 可编译并有对应 PDF。
5. 论文数字、表格、图表与结果文件一致。
6. 引用已核实，没有虚构来源。
7. 日志已更新，后续人员能从中继续。
8. 未完成项、风险和限制已明确说明。
